# 모델 선정 근거 — 자가 촬영 상품 사진 배경/조명 정제 PoC

PoC 코드([`src/mask.py`](../src/mask.py), [`src/segment.py`](../src/segment.py), [`src/inpaint.py`](../src/inpaint.py), [`app.py`](../app.py))에서
사용한 모델을 선정한 근거를 정리한다. 상품 영역 분할과 배경 재생성 두 단계 각각에서 대안을 검토하고 골랐다.
(초기 기획 단계에서 "워터마크 제거" 문제로 논의했던 비교를 현재 "배경/조명 정제" 목표에 맞게 다시 정리한 것 —
배경 피벗 경위는 [`PROBLEM_DEFINITION.md`](PROBLEM_DEFINITION.md) 참고.)

## ① 상품 영역 분할 — YOLOv8-seg vs SAM vs rembg

| 모델 | 방식 | 장점 | 단점 |
|---|---|---|---|
| YOLOv8-seg (1차 PoC에서 사용, 폐기) | 클래스 기반 자동 탐지+분할 | 프롬프트 설계 불필요, 가볍고 빠름, 모듈에서 다룬 YOLO 계열 | 학습되지 않은 상품 카테고리는 인식 못할 수 있음. **AGPL-3.0 라이선스 — 매출을 발생시키는 제품·서비스에 통합하려면 전체 오픈소스 공개 또는 Ultralytics Enterprise License 구매가 필요** |
| SAM | 포인트/박스 프롬프트로 분할 | 범용성·정확도 최고 | 프롬프트 로직을 별도로 설계해야 하고 무겁고 느림 |
| **rembg / U2-Net (채택)** | 배경 제거 전용 경량 모델 | 세팅이 가장 간단, 단일 객체 사진에 결과가 깔끔한 경우 많음, **MIT 라이선스로 상업적 이용 제약 없음** | 모듈에서 다룬 계열은 아님, 클래스 인식은 하지 않음(단일 전경/배경 분리만) |

**선정 이유(1차)**: 초기에는 YOLOv8-seg를 채택했다. 학습된 클래스 기반으로 곧바로 분할이 가능해 구현
속도가 빠르고, 모듈에서 다룬 YOLO 계열에 속해 적용 근거가 명확했기 때문이다. 실제로 상품이 COCO
80종에 없는 경우(효도박스, 스피커 등) 탐지에 실패하는 한계가 발견되어, 면적 비율 필터링 + GrabCut
폴백을 추가로 구현했다.

**모델을 rembg로 교체한 이유**: 처음엔 라이선스를 전혀 의식하지 않고 YOLOv8-seg 그대로 커밋·푸시할
계획이었다. 그런데 커밋 직전 다른 수강생들의 과제 README를 둘러보다가 Ultralytics YOLOv8이 AGPL-3.0
라이선스라 실사용 시엔 상업적 제약(매출을 발생시키는 제품에 통합하려면 전체 오픈소스 공개 또는
Enterprise License 구매 필요)이 있다는 걸 뒤늦게 의식하게 됐다. 이때 1차 PoC에서 YOLOv8-seg의 실패율이
꽤 높게 나왔던 것(상품이 COCO 80종에 없으면 탐지 자체가 안 됨)도 이미 알고 있던 터라, "어차피 실패율도
높은데 상업적으로 쓸 수 있는 라이선스 중엔 더 나은 대안이 없을까"라는 생각으로 rembg와 비교해 같은
20장을 다시 돌려봤다. 즉 이 교체는 실사용 계획이 있어서도 아니고 라이선스와 무관하게 순수한 호기심에서
나온 것도 아니며, **다른 사람 작업물을 보고서야 라이선스를 인지한 계기와 이미 갖고 있던 정확도 불만이
겹쳐서** 이어진 결정이다. rembg는 클래스 인식이 필요 없는 "전경/배경 분리 전용" 모델이라 COCO 클래스
밖 상품에서도 탐지 실패 없이 20장 전체에서 안정적으로 동작했다(GrabCut 폴백 미사용, 자세한 수치는
[`RESULTS.md`](RESULTS.md) 참고). 다만 클래스 정보가 없어 "이게 상품인지 잡동사니인지"를 구분하는
판단은 여전히 면적 비율 휴리스틱에 의존한다.

## ② 배경 재생성 — Diffusion inpainting vs LaMa vs OCR+inpainting

| 모델 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **Diffusion inpainting (채택)** | 마스크 영역을 생성형으로 채움 | 넓은 영역도 자연스러운 텍스처로 복원, 모듈에서 다룬 생성형 계열 | 무겁고, 가끔 배경과 무관한 내용을 "환각"으로 채워 넣음 |
| LaMa | inpainting 특화 경량 모델 | 국소적인 영역(워터마크 등)을 지우는 데 diffusion보다 안정적이고 빠름 | 배경 전체를 새로운 장면으로 "생성"하는 용도엔 덜 적합, 모듈 밖 모델 |
| OCR 탐지 + Diffusion inpainting | 텍스트 영역 자동 탐지 후 inpainting | 마스크를 수동으로 안 그려도 됨 | 모델이 두 개 엮여 구현 복잡도 증가, 배경 전체 재생성이라는 이번 문제와는 결이 다름 |

**선정 이유**: Diffusion inpainting은 텍스처 복원이 자연스러워 "상세페이지에 바로 쓸 수 있는 수준"이라는
목표에 부합한다고 판단해 채택했다. 다만 20장 실제 테스트 결과 이 장점이 곧 단점으로도 나타났다 —
inpainting 대상 영역이 넓거나 배경이 어두울수록 "clean studio background" 프롬프트를 모델이 과하게
해석해 조명 장비, 장식품, 심지어 상품 자체의 복제본까지 만들어내는 "오생성" 사례가 발생했다. rembg로
마스크 품질을 개선한 뒤에도 오생성 비율은 7/20건으로 여전히 남아있어([`RESULTS.md`](RESULTS.md) 참고),
이 한계는 분할 모델이 아니라 diffusion 모델/프롬프트 자체에 있다는 게 확인됐다. 배경을 비우기만
하면 되는 케이스라면 LaMa 쪽이 더 안전한 선택이었을 수 있다는 것도 이번 PoC로 확인한 한계다.

## ③ 합성
분할된 상품 픽셀과 diffusion이 생성한 배경을 페더링(feather) 마스크로 블렌딩해 경계를 자연스럽게
만든다 (`feather()` in `src/mask.py`).
